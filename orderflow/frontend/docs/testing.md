# Testing and evidence

`npm run test` executes Vitest/RTL/MSW tests of actual feature components and API transport. Coverage includes exact money, return URLs, pagination shapes, CSRF/refresh/epoch/account switching, cookie-write ordering, field/rate errors, public/private cache behavior, product/category invalidation, forms, ownership failures, stable uncertain attempt keys, bounded polling, notification preferences and SSE parsing. Regression changes were tested failing before fixes and passing after them; this is not a percentage coverage claim.

`npm run test:e2e` runs Chromium fixture tests for public/customer/vendor/agent/admin pages, cart/auth/role guard/payment pending/tracking, mobile overflow/keyboard navigation and unavailable gateway behavior. Gateway fixtures are confined to `e2e/support/fixtures.ts`; production code never imports them. Desktop/mobile screenshots are in ignored `output/playwright/`.

`npm run test:e2e:real` requires `ORDERFLOW_REAL_E2E=true` and a local real gateway/Docker stack. It registers unique new accounts, grants staff roles only to returned fixture UUIDs, exercises four actual browser sessions, creates a category/product/stock, restores a customer HttpOnly-cookie session, changes the cart, checks out, confirms payment, signs a trusted callback, checks paid/stock/delivery/notification state, completes an agent delivery and a partial refund, checks ownership/role denial and logs out. Trace/video and form-value failure snapshots are disabled for real accounts. Tests leave their uniquely named local data for inspection and never delete user volumes.

Java regression verification uses Java 21 and `./mvnw -B -ntp clean verify`, including the existing Docker-backed integration suites. On the local Documents FileProvider filesystem it runs in a byte-identical source copy under `/tmp/orderflow-phase9-backend`, excluding generated targets/frontend and private environment files. This avoids generated class duplication and sync stalls. Do not run the full stack or Chromium concurrently with Kafka Testcontainers on a 4GB Docker VM.

Final executed counts, exit codes, resource-related retries, dependency audit limitations, image/health checks and NOT RUN external flows are recorded in [phase9-verification.md](phase9-verification.md). GitHub-hosted CI is not considered executed merely because equivalent local commands pass.
